# 編み図メーカー v2（Knit Chart Maker）

タブレット・スマホでの利用を第一優先にした編み図作成ツール。ビルド不要の素の
HTML/CSS/JS で、`index.html` をブラウザで開くだけで動作する。npm等の依存なし。

このREADMEは「新しいチャットでAIアシスタントに続きの開発を依頼するときに、
前提を素早く共有するためのメモ」として書かれている。公開手順ではなくアプリの
構造・仕様・これまでの経緯をまとめてある。

## 技術構成・お約束

- 素の HTML / CSS / JS。フレームワークなし、ビルドステップなし。
- 各JSファイルは `(function (KC) { "use strict"; ... })(window.KC);` のIIFEで、
  `window.KC` 名前空間に機能を生やす形（例: `KC.state`, `KC.grid`, `KC.selection`）。
- モジュール間の連携は `js/bus.js` の簡易イベントバス（`KC.bus.on(event, fn)` /
  `KC.bus.emit(event, payload)`）経由。直接関数を呼び合うのではなく、
  `rowsChanged` / `sizeChanged` / `dataReplaced` / `selectionChanged` /
  `rangeSelectionChanged` / `toast` などのイベントで疎結合に連携している。
- UIの状態表示は基本的に `classList.toggle("is-active", ...)` /
  `classList.toggle("is-hidden", ...)` の2クラスで統一（独自のdisplay切り替えを
  あちこちに書かない）。
- ボトムシート（`row-sheet` / `preset-sheet` / `guide-line-sheet`）は共通の
  `.sheet-backdrop` + `.row-sheet` クラスとハンドルのスワイプ閉じ処理を使い回している。
- グリッド本体は `<canvas>` に手描きしている（DOM要素を1マスずつ作っていない）。
  ズーム・パン・ピンチはすべて `js/canvas-grid.js` の `view = { scale, tx, ty }` を
  介した独自のアフィン変換で実装。

## ファイル構成と役割

- `index.html` … 全UIのマークアップ。タブ4つ（編み図/毛糸/サイズ/書き出し）
  ＋各種ボトムシート＋トースト＋ローディングオーバーレイ。
- `css/style.css` … 全スタイル。
- `js/bus.js` … イベントバス（上記）。
- `js/state.js` … データモデルの単一の入り口。UIに一切依存しない純粋ロジック層。
  行・毛糸・ガイド線のCRUD、JSON入出力の正規化もここに集約。
- `js/storage.js` … localStorageへの自動保存（デバウンス）。モバイルでの
  `beforeunload` 不発火対策として `pagehide` / `visibilitychange` でも保存する
  （後述の「ハマったポイント」参照）。
- `js/canvas-grid.js` … グリッド本体の描画・タップ/ドラッグ/ピンチ/長押しの
  ジェスチャー処理。行番号ガター・目番号ガター・毛糸番号ラベル・
  選択オーバーレイ・範囲選択オーバーレイ・ガイド線もここで描画。
- `js/selection.js` … 「複数行操作」モード（行単位のチェック選択・コピペ・undo・
  2点タップでの範囲選択＝`handleRowTap`/`isRangePicking`）。
- `js/range-select.js` … マス単位の矩形範囲選択モード（2点タップで矩形指定→
  コピー→別マスをタップして貼り付け、上下/左右反転貼り付け、undo対応）。
- `js/sheet.js` … 1行を編集するボトムシート（繰り返し目数・地/柄の色・削除）。
- `js/yarn-tab.js` / `js/yarn-presets.js` / `js/preset-sheet.js` … 毛糸タブ、
  グループ分けされた定義済み毛糸リスト（`KC.presetGroups`、ユーザーが直接
  書き換える想定のデータファイル）、リストから選んで追加するシート。
- `js/size-tab.js` … サイズタブ。行数/目数の数値入力＋±クイックボタン＋
  増減方向トグル（行=上/下、列=左/右）＋「サイズを反映」。
- `js/guide-lines.js` … サイズタブ内のガイド線機能（後述）。
- `js/export-tab.js` / `js/json-io.js` / `js/png-export.js` … 書き出しタブ、
  JSON保存/読込、PNG書き出し（A4縦・150dpi相当、Canvasで独立描画）。
- `js/loading.js` … 全画面ローディングオーバーレイ（最低表示時間あり、後述）。
- `js/howto.js` … 使い方モーダル。
- `js/main.js` … 初期化・タブ切り替え・「編む」画面上部ツールバーの状態管理
  （通常/複数行選択/範囲選択の3状態をここで一元管理）。

## データモデルの要点（`state.js`）

- `state = { cols, yarns: [], rows: [], guideLines: [] }`
- 行 (`row`) は `{ uid, repeat, stitches: bool[], bg, fg, offset }`。
  **繰り返しタイル方式**：`repeat` 目分のパターンを `offset` だけずらして
  `cols` 目ぶん繰り返し表示する。実際の目の状態は
  `stitchAt(row, colIndex) = row.stitches[normalizeOffset(colIndex + offset, repeat)]`
  で参照する（列ごとに独立した配列を持っているわけではない）。
  「繰り返しを解除」すると `repeat = cols` になり実質1目ずつの配列になる
  （`isRepeatReleased(row)` は `repeat >= cols` で判定）。
- **行の並び順と画面表示の対応が直感と逆**：`state.rows` 配列の**末尾**が
  画面の**一番上（行番号が一番大きい）**、配列の**先頭**が画面の**一番下**
  （行番号1）。`canvas-grid.js` 側で
  `rowNumber = rows.length - displayIndex` と変換している。行の追加/削除方向
  （「上/大きい番号側」「下/小さい番号側」）を扱う関数はすべてこの対応を
  踏まえて実装されている。新しくこの並びを触るコードを書くときは要注意。
- 列方向の増減（`addColumn`/`removeColumn`）も方向指定（左/右）に対応。
  タイル行はoffset調整、繰り返し解除済みの行は`stitches`配列を直接
  unshift/shift・push/popして対応している。
- `guideLines`：1エントリ＝**1セットで2本**の縦線。
  `ref: "edges"`（左右の端からそれぞれoffset目）または`"center"`
  （中央から左右にoffset目ずつ）。`guideLineBoundaries(gl)` が実際の
  境界位置（0〜cols、マス目の縦線と同じ座標系）を配列で返す
  （2本重なる場合は1本にまとめる）。色・太さは1セット共通。
- `repeatMax()`：繰り返し目数の上限は固定値ではなく**現在の目数(cols)**。
  サイズが変わると連動する。

## これまでに実装した主な機能（時系列でだいたいこの順）

1. 複数行操作モード（チェック選択・コピペ・上下反転貼り付け・色だけ/柄だけ貼り付け・undo）
2. localStorage自動保存・復元
3. 行数増減の方向指定（上/下）、繰り返し解除、目番号表示、5の倍数を目立たせる
4. 毛糸リストのプリセット化・グループ分け
5. マス単位の矩形範囲選択（コピー・貼り付け・上下/左右反転貼り付け・undo）
6. 毛糸リストをグループ化（`KC.presetGroups`）
7. プロジェクト読込/PNG書き出し時のローディングスピナー、列削除ボタン、
   アイコン追加
8. 編み図の最大サイズ 300×300 → 1000×1000
9. 列数増減の方向指定（左/右）、サイズタブUI整理（行/列ごとにカード化）
10. 用語統一：「行」→「段」、「列」→「目」（表示文言のみ。内部の変数名等は
    そのまま`row`/`col`）
11. 各段で使用している毛糸の番号（地/柄）を段番号ガターの右に表示
12. **ガイド線機能**（サイズタブ）：位置（左右の端から／中央から）・色・太さを
    指定できる縦のガイド線。マス目の縦線と同じ位置に表示され、PNG書き出しにも
    反映される。1セット2本（左右対称）。一覧から個別に削除も可能。

## ハマったポイント・設計判断のメモ

- **モバイルは `beforeunload` がほぼ発火しない**。自動保存を
  `beforeunload` だけに頼るとタブを閉じた瞬間の未保存分（デバウンス待ち500ms）が
  消える。`pagehide` と `visibilitychange`（`hidden`時）でも保存するようにして解決。
- **ファイル選択ダイアログを開いてから`change`イベントが発火するまでは
  JS側では何も検知できない**（特にクラウドストレージ上のファイルを選ぶと数秒
  かかることがある）。対策として、ダイアログを開いた瞬間（`click`イベント）
  からローディング表示を出しておく方式にした。
- ローディングオーバーレイは**最低表示時間（500ms）を保証**している。
  処理が一瞬で終わるとスピナーが一瞬すぎて見えないため。
- `requestAnimationFrame`の二重呼び出しでの「描画を1フレーム待つ」手法は、
  ファイル選択ダイアログから復帰した直後など特定のタイミングでは信頼できず、
  `setTimeout`に置き換えた実績がある。
- PNG書き出しは編集画面とは別の固定解像度（A4縦・1240×1754px）でCanvasに
  再描画する完全に独立した実装。セルサイズや線の太さの見た目を編集画面と
  揃えたい場合は、両方の実装（`canvas-grid.js`と`png-export.js`）に
  同じロジックを重複して書く必要がある（`BASE_CELL`=26 と
  `png-export.js`側の`REF_CELL`=26 が対応関係にある）。
- 行編集シートの繰り返し目数入力は、+/-ボタンだけでなく直接数値入力できる
  `<input type="number">` に変更済み。
- ガイド線のボトムシートは、フィールドを触るたびに即座に`state`へ反映する
  「ライブ編集」方式（他のシート類と同じ流儀）。ただし新規追加時は
  何も触らないと何も作られない問題があったため、明示的な「追加」ボタンを
  別途設けて解決した。

## 開発の進め方（このAIアシスタントとのやり取りの経緯）

- 基本は「どのファイルの何行目をどう直すか」という**差分指示**でメッセージ数を
  節約する方針（フルファイルの再掲は極力避ける）。
- ただし何度か「AIが把握しているコードの中身」と「手元の実ファイル」が
  ズレて、指示した行番号が合わない事故が起きた。ズレを感じたら
  `.git`込みでzip化して渡すと、AI側で実ファイルを直接開いて確認・修正できる
  （このリポジトリは元々git管理されており、コミットログに変更の経緯が残っている）。
- 新しいチャットを始める際は、このREADMEと合わせて最新のzip（または該当ファイル）
  を渡すとスムーズ。
